# Pi Remote

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People continuing local Pi coding sessions from a phone, including supervising concurrent work.

## Product purpose

Read conversations, send instructions, and control the selected Pi session without returning to the computer.

## Operating context

The phone normally connects through opentunnel to a local Pi Remote host. Render is an optional relay. Desktop browsers also use the interface.

## Capabilities and constraints

Session context, messages, drafts, attachments, model settings, and Stop are session-specific. Design studies must distinguish sample activity from actual execution. Preserve the production composer and all its controls unless the user explicitly requests a composer change.

## Brand commitments

Keep Pi Remote recognizable. New orchestration layouts may change information hierarchy and navigation, but must retain the existing interface's typography, control language, and theme support.

## Evidence on hand

`web/index.html` and `web/style.css` define the working interface. `docs/research/coordinator-visual-directions.md` records first-party visual references and the constraints confirmed in the coordinator design discussion.
