# Coding and reviewed integration

The same main conversation delegates real development tasks and remains the only human input destination. Its workers edit separate detached Git worktrees. Their logs remain inspection-only.

## Drive

Run the full coordinator proof. After its investigation assertions, it initializes only its disposable fixture project as a Git repository and preserves an unrelated untracked draft and staged change.

1. Send `Fix the fixture calculation with two workers.` in the original conversation. Require Calculation fix and Coding notes to own distinct worktrees and real Pi PIDs. Calculation fix edits calc.mjs, runs a Node assertion, writes checks.txt, then reports. Coding notes writes its own file and remains active. Parent calc.mjs must still be unchanged.
2. Inspect the returned calculation diff. Send a task-scoped revision instruction, then try the old revision. Require rejection without parent edits and keep the result available for review.
3. Add a conflicting edit only to the fixture parent's calc.mjs. Integration must reject it, preserve it byte-for-byte, and leave the staged index unchanged. Restore only that owned fixture edit.
4. Send `Review and integrate the calculation fix.`. The deterministic parent uses inspect, reads the returned diff/revision, then integrate. Require the edited calculation and new files in the parent, completed state, preserved draft/index, and no Coding notes file copied across.
5. Repeat the exact integration request ID and require the cached outcome rather than another apply. Another parent and a worker capability must not integrate this task.
6. Inspect Calculation fix in the phone sheet. Task details identifies its workspace and integrated state. The original main composer is still the only input.
7. Restart the owned fixture host. Require the integrated result and both worktree paths to survive, the active notes task to resume from its saved history with a recovery note, and no duplicate original input body or notes-file write. Send `Stop the coding notes worker.` in the main conversation and require only that task to stop.

## Evidence and limits

Native provider audit must include successful edit/write/bash calls, the assertion output, unavailable Pi Remote shell environment secrets, and rejected file-tool writes outside the worktree and through a dangling symlink. Real files and saved task records must corroborate the visible result. Retain coding-audit.json and coding-workspace-integrated.png alongside the full proof.

This is not a paid-model planning check, a shell sandbox, a submodule integration proof, or an assertion that arbitrary repository checks will pass. Worktree file isolation does not confine hostile shell commands.
